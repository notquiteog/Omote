          Create something

          Edit something you already have

          Trim, cut, join, pull frames out, change the speed, drop the sound or burn in subtitles for a clip; crop, resize, rotate, flip, sharpen or convert for a picture. Nothing is overwritten — every edit is a new file beside the original, with the operation recorded so you can change one thing and run it again.

          Worktrees

          A second checkout of this repository, on its own branch, that a session works in — so a turn cannot touch the tree you have open. The branch is there afterwards to merge, look at, or throw away.

          Hooks

          Commands that run around a tool call. One that exits non-zero stops the call and its reason goes back to the model — a hook can take things away and can never allow them, so a project can stop you doing something without being able to do it for you.

          Yours in ~/.omote/hooks.json run as written. A project's are code you did not write, so the first time one would fire you are asked, and the answer lasts for the session.

          Review this turn's changes

          Each block is one change. Put back the ones you disagree with and leave the rest — the undo of "the agent changed this and got it right" is not the undo of the turn. Nothing is written until you press the button.

          Rewind

          Put files back to how they were before a turn. This undoes that turn and every one after it — undoing one in the middle would leave a state that never existed.

          Only the agent's own file edits are recorded. Anything a shell command wrote is not covered, and cannot be: snapshotting the whole filesystem before every command is not something anyone wants.

      Omote checks GitHub for a newer release and tells you. It never downloads or
      installs anything on its own: downloading waits for you to press the button, and
      installing waits for you to confirm, because a message that appears over work you are
      doing is a message that gets dismissed without being read.
    
                
    
                
    
                
    
                
    
                
    
      
      
                
      
      
                    
    
                
      
      
    
                
    
                
      A downloaded installer is checked against the SHA256 published in the same release before
      it is offered to run. That is an integrity check, not a signature: it catches a truncated
      download and a mirror serving last week's build, and it does not prove who published
      anything.
